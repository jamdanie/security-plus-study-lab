# Learn through a tabletop exercise

[Hands-on missions](hands-on-missions.md) · [Contents](../study/contents.md)

A tabletop uses a scenario and discussion to practice decisions. You can use it when software is unavailable, or pause a game to discuss the response to an observed failure.

## Free supporting material

[CISA Tabletop Exercise Packages fact sheet](https://www.cisa.gov/sites/default/files/2023-02/ctep_fact_sheet_v._11_16_2021_final.pdf) describes CISA's exercise resources. Use the official document's guidance and links to find packages relevant to your group. Check the chosen package's scope and instructions before using it.

Our [availability tabletop](../labs/30-availability-tabletop/README.md) is an original small study exercise. It is not a CISA package or an official exam task.

## Make the exercise useful

Choose a narrow goal, such as recognizing when to engage a network provider. Read the opening condition, make a decision, then reveal the next update. Record who acts and what evidence would show progress.

A decision can be reasonable with incomplete information. State the assumption that supports it and what evidence might change it.

## Connect it to visual learning

Draw the affected users, service, and provider. Mark where evidence was collected. If internal checks pass but external access fails, explain why those checks observe different paths.

A data center game can supply an observation to discuss, but a discussion cannot establish real technical recovery time. Keep actual simulator observations separate from the fictional scenario.

## Finish with a correction

Write one process gap, an owner role, and a verification method. For example, if the scenario exposes an outdated contact list, propose checking the revised escalation route. This is a proposed follow-up until someone actually performs it.
