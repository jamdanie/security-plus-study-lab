# Visual session: inspect, decide, and verify

[All missions](hands-on-missions.md) · [Game comparison](steam-data-center-games.md)

Use this session to explain how a security claim is checked and how an automated change stays within its scope. No purchase or installation is required.

| Step | Activity | Result to keep |
|---|---|---|
| Inspect | [Control evidence](../labs/43-control-evidence/README.md) | Requirement, evidence scope, period, and gap |
| Decide | [Automation review](../labs/44-automation-review/README.md) | Approved target list and stop condition |
| Verify | [Four review questions](../practice-tests/evidence-and-automation-24.md) | Reason for each answer |

## Make it visual

Draw a box for each system named in the evidence. Attach the relevant record to that system. Mark which records describe old observations, current settings, or a person's statement.

For the automation exercise, draw the input list crossing an approval boundary. Identify the unapproved target before drawing any change action.

If you use a game, capture a supported setting and label what it establishes. Do not claim that a game score proves fleet-wide compliance or successful automation.

## Change one condition

Replace an old screenshot with a current test, or remove the unapproved device from the input list. Explain which gap is resolved and which verification is still needed.

The activities support partial SY0-701 5.5 and 4.7 concepts. They do not certify a real environment or replace the full exam objectives.
