# Exercise 33: apply a data-handling policy

[Data states](../../concepts/data-states.md) · [Contents](../../study/contents.md)

Offline fictional exercise. Partial SY0-701 3.3. Ready to try. Labels and handling rules below belong only to this scenario.

## Policy

Public material is approved for public release. Internal material is limited to staff using approved company services. Restricted material is limited to named authorized recipients using the approved restricted workspace. Public repositories are not approved for Internal or Restricted material.

| Item | Label | Proposed action |
|---|---|---|
| A: approved public brochure | Public | Publish in the public project |
| B: internal rack map | Internal | Upload to a public repository |
| C: fictional payroll export | Restricted | Share with named authorized recipients in the approved restricted workspace |
| D: same export renamed notes.txt | Restricted | Upload to a public repository |

Identify permitted and prohibited actions. Explain whether renaming D changes its classification.

<details>
<summary>Worked review</summary>

A and C follow the stated policy. B exposes Internal data in an unapproved destination. D remains Restricted regardless of filename and violates the same destination rule.

Changing a file's extension, name, or visual appearance does not change the policy assigned to its contents. An actual reclassification needs the organization's authorized process.

</details>

## Visual extension

Draw each item moving from its source to its proposed destination. Label the trust boundary and the condition required before sharing. Use fictional content for any screenshots or portfolio notes.

If a simulator lacks data labels or access controls, record that limit. Do not treat visible traffic or a successful upload as proof that sharing was authorized.
