You rename a file without changing its bytes. What happens to its SHA-256 hash?<br>A. It changes because the filename changed.<br>B. It stays the same.<br>C. It becomes encrypted.<br>D. It disappears.<br><br>Think: What does a content hash measure?	Correct: B. It stays the same.<br><br>Why: SHA-256 (Secure Hash Algorithm with a 256-bit output) hashes the file contents. A is incorrect because the filename is not part of the input to this content hash. C is incorrect because hashing does not encrypt the file. D is incorrect because renaming does not prevent computing its hash.<br><br>Key idea: Same bytes and algorithm, same hash.	security_plus hashing lab_01
Your file's SHA-256 hash differs from a trusted reference hash. What can you conclude?<br>A. The file definitely contains malware.<br>B. The file has the same bytes as the reference file.<br>C. The file's bytes differ from the reference file.<br>D. The hash tells you who changed it.<br><br>Think: Separate evidence of a difference from evidence about its cause.	Correct: C. The file's bytes differ from the reference file.<br><br>Why: With the same algorithm, identical bytes produce identical hashes. A is incorrect because corruption or an ordinary edit can also explain the difference. B contradicts the mismatch. D is incorrect because a hash does not identify an editor.<br><br>SHA-256 means Secure Hash Algorithm with a 256-bit output. Key idea: A mismatch shows a difference, not its cause.	security_plus hashing lab_01
