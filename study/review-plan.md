# Build a review session around one weak section

This is a suggested workflow, not a validated passing formula. Adjust the time and difficulty to your needs.

## A 25-minute session

| Time | Action | Output |
|---|---|---|
| 0–3 minutes | Choose one weak topic from the contents | State the question you cannot yet answer |
| 3–10 minutes | Read its example and close the page | Explain the decision in your own words |
| 10–18 minutes | Attempt the linked exercise or questions | Record choices before opening answers |
| 18–23 minutes | Review errors and guesses | Explain why the nearest alternative fails |
| 23–25 minutes | Set the next check | Choose a changed scenario to explain later |

Use the [table of contents](contents.md) to find the route. If a term is blocking you, open the linked short concept page rather than restarting an entire course.

## Record the useful part of a mistake

Write a local note with the topic, question reference, missed requirement, corrected explanation, and next verification. Avoid copying only an answer letter.

Example: "I selected encryption because the file was important. The requirement was public verification of a signer, so a digital signature with a trusted key fits. Next I will explain what changes if the file must also remain private."

That example is fictional; no learner result has been recorded.

## When the question is correct but uncertain

Mark it as a guess. Explain why the answer meets the stated scope and why one plausible alternative does not. Being able to recognize a remembered answer is weaker evidence than explaining a changed example.

## Broaden after targeted review

Return to a mixed set periodically to practice changing topics. Use the [exam alignment](exam-alignment.md) to avoid ignoring domains just because the repository has fewer pages about them. Short-set scores cannot establish full exam readiness.
